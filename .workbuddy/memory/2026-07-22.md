## 添加记录页保存按钮 iOS 需点两次（用户需求）
- 现象：iOS 上，添加记录页（Record.vue）「保存记录」按钮有时要点两次——第一次 tap 仅让输入框失焦/收起键盘，第二次才触发 `click` 保存。原因：iOS Safari 在输入框获焦、键盘未收起时，点击按钮的第一下 tap 被用作收起键盘（输入框 resign first responder），不派发 click 给按钮。
- 修复（`frontend/src/views/Record.vue`）：给保存 `n-button` 加 `@touchend.prevent="onSaveTouch"`；`onSaveTouch` 先 `document.activeElement?.blur()` 收起键盘，再调用 `submit()`；`.prevent` 抑制随后合成的 click，避免重复提交；`loading` 时直接 return 防重入。非触摸端（桌面）仍走 `@click`。
- 验证：`pnpm build` 通过，重启后端(26712)后 health 正常（v0.0.25）、首页加载新 JS（index-ReR4jIve.js）。代码改动未提交，待用户指令。
- 备注：同一问题在首页编辑记录弹窗（Home.vue 的保存按钮）同样可能存在，但用户本次仅要求添加记录页；如需一并修复 Home 编辑弹窗，可按同样方式加 `@touchend.prevent`。

## 隐藏日期对话框的秒数（用户需求）
- 现象：所有 `datetime` 类型 `n-date-picker`（Record.vue 的 occurredTs/sleepStart/sleepEnd/playStart/playEnd，Home.vue 的 eTs/eSleepStart/eSleepEnd/ePlayStart/ePlayEnd）在面板里时间选择区始终显示「秒」列、时间输入框也显示到秒。根因：datetime 面板的时间选择器用的是 `timePickerFormat`，其默认值（`node_modules/naive-ui/.../use-panel-common.js` 的 `TIME_FORMAT='HH:mm:ss'`）并非组件上传入的 `format="yyyy-MM-dd HH:mm"`；`datetime.js` 渲染 `NTimePicker` 时 `format: this.timePickerFormat` 固定用 `HH:mm:ss`，故秒列始终渲染。
- 修复：给两文件所有 `type="datetime" format="yyyy-MM-dd HH:mm"` 的 `n-date-picker` 加 `:time-picker-format="'HH:mm'"`（replace_all）。`NTimePicker` 的 `secondInFormat` 由 format 推导（含 'ss' 才显示），改 `HH:mm` 后秒列不再渲染、时间输入框也只到分钟，UI 秒数彻底消失。Home.vue 的 `type="date"`（selectedTs 日历、addBirthdayTs 生日）不受影响。
- 验证：仅前端 `pnpm --filter frontend build` 通过（2888 模块，4.6s）。代码改动未提交，待用户指令。
- 备注：UI 隐藏秒后，保存的时间戳仍可能带「打开面板时的当前秒」（新建）或「编辑回填的秒」（已有记录），列表显示只到分钟看不出差异，但库里秒值非零。如需存储也归零到分钟，需在提交/回填处把秒(毫秒)清零（Record.vue submit 与 Home.vue 各编辑保存分支），属额外范围，未做。
- 补充（用户反馈「还是有秒数可以选择」，排查）：根因是**预览访问的后端服务(26712)提供的是 `backend/dist/public`，而之前只跑了 `pnpm --filter frontend build`**——它只更新 `frontend/dist`，不会复制到 `backend/dist/public`，所以线上仍是含秒的旧前端。正确流程：改前端后必须跑**完整 `pnpm build`**（tsup 的 copy-frontend 会把最新前端复制到 `backend/dist/public`），再重启后端(26712) 进程才生效。本次最终做法：① 两文件加 `:time-picker-format="'HH:mm'"`；② `frontend/src/styles.css` 加 CSS 兜底 `.n-date-panel--datetime .n-time-picker-col:nth-child(3){display:none!important}`；③ `pnpm build`；④ `kill -9 <旧PID>` 后重启 `node backend/dist/server.js`。验证：`curl /api/health` 正常；`curl /` 引用 JS 为 `index-hPkSEBVl.js`（与 build 产物一致）；该 JS 含 3 处 `timePickerFormat` 绑定 → 属性已进产物。用户刷新（建议硬刷新 Cmd/Ctrl+Shift+R）后秒消失。
- 经验：让 26712 预览生效前端改动 = `pnpm build` + 重启后端；仅改 `frontend/src` 时 vite dev(5173) 会 HMR，但线上预览走的是 `backend/dist/public`。验证前端是否进产物：`curl /` 取 JS 名 → `curl` 该 JS → `grep timePickerFormat`。
